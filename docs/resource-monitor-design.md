## 目标与首版范围

制作一个轻量、可逐步扩展的 ComfyUI custom node 项目，首个功能是在菜单栏实时显示本机资源使用情况。首版作为界面扩展加载，不要求用户在工作流中添加节点。

用户已确认以下范围：

| 指标 | 菜单栏显示 | 统计口径 |
| --- | --- | --- |
| CPU | 利用率 | ComfyUI 所在主机整体 CPU 的采样间隔利用率 |
| 内存 | 占用率；悬浮显示已用／总量 | 主机物理内存；已用为总量减去可用内存 |
| GPU | 利用率 | 所选 NVIDIA GPU 的整卡利用率 |
| GPU 温度 | 摄氏温度 | 所选 NVIDIA GPU 的驱动温度读数 |
| 显存 | 占用率；悬浮显示已用／总量 | 所选 NVIDIA GPU 的整卡显存，包含其他进程占用 |

CPU 温度和磁盘指标已由用户明确移出首版。首版不依赖 LibreHardwareMonitor。工作流执行进度条、节点工具、历史统计及模型操作不属于本次范围。

## 界面与设置

- 通过当前 ComfyUI 前端保留的 `app.menu.settingsGroup.element` 扩展入口，将资源条放在菜单栏。首版以本机前端 1.53.10 为验收基线。
- 使用原生 JavaScript 和 CSS，不引入 Vue、React 或前端构建工具。数值刷新只更新已有元素，避免反复重建资源条。
- 默认显示全部五项指标，每秒刷新。使用 ComfyUI 的扩展设置注册机制，提供各项显示开关、刷新间隔和 GPU 选择；刷新间隔为 0 时关闭监控。
- GPU 选项由后端实际枚举结果提供。默认选择第一张可用 NVIDIA GPU；无可用 GPU 时，GPU 相关指标显示“不可用”。
- 外观参考 Crystools：采用 60×30px 彩色填充资源条，标签左下、读数右上；CPU/RAM 为绿色，GPU/VRAM 为蓝色，温度使用 0–100°C 色阶。深灰卡片底色保持深浅主题的读数对比度。内存和显存容量保留在悬浮详情。窄窗口在资源条内横向滚动，不阻挡菜单操作。
- 百分比显示 `%`，温度显示 `°C`，内存与显存按 GiB 展示。单位与统计口径保持一致。
- 页面隐藏、监控关闭或资源条所在菜单不可见时暂停刷新，恢复显示后重新取得数据。Focus Mode 和浮动菜单切换后应能恢复挂载。

## 组件与数据流

扩展由三个职责清楚的部分组成：

1. **加载入口**：通过 `WEB_DIRECTORY` 注册前端文件，通过空的 `NODE_CLASS_MAPPINGS` 允许 ComfyUI 加载扩展，注册本扩展的本地资源接口。
2. **资源采集器**：使用 `psutil` 采集 CPU 和内存，使用 `nvidia-ml-py` 提供的 `pynvml` 接口采集 NVIDIA GPU 指标。采集器持有必要的采样基线、驱动句柄及小型近期快照，不接触模型、工作流或队列。
3. **菜单栏界面**：通过同源 ComfyUI API 获取资源快照，按当前设置展示对应指标；设置保存在 ComfyUI 自身的设置系统中。

数据流为：菜单栏请求 → 扩展本地接口 → 资源采集器 → 数值快照 → 菜单栏更新。不会修改 ComfyUI 核心源码或模型执行路径。

拟使用 `GET /enhance-kit/resources` 提供快照。数据只包含采样时间、CPU 利用率、内存数值，以及 GPU 的索引、名称、利用率、温度和显存数值。容量在接口中使用 bytes，温度使用摄氏度，利用率使用百分数；缺失数值使用 `null`，不得使用 0 或旧数值冒充有效实时读数。

GPU 数据逐项表示可用性：单个驱动指标不支持时，其他可用指标继续显示。GPU 索引与显示选项均来自服务端枚举，不接受客户端传入任意命令、设备路径或文件路径。

## 采样与失败处理

- 采集工作与 ComfyUI 主事件循环隔离，不使用阻塞式 CPU 百分比采样等待。CPU 百分比使用明确的前后采样基线，首次基线尚不足时显示“采样中”。
- 同一时刻至多执行一次资源采集；多个页面共享近期快照，避免重复采集和互相修改设置。前端请求不重叠。
- 导入扩展时不启动无限监控循环。没有界面请求时不持续采集；正常清理阶段释放驱动资源。
- 不导入 torch 或创建 CUDA 上下文来获取监控数据。缺少 NVIDIA 依赖、没有 NVIDIA GPU、驱动不可用或某项指标不支持，均不影响 CPU 和内存显示，也不阻止 ComfyUI 启动。
- 数据请求失败或超过有效期时，界面显示“不可用”；恢复后更新为新读数。错误信息应简短，不在每个刷新周期重复打印日志。
- 扩展运行期间不访问互联网、不上传资源数据、不安装或启动额外监控软件。

## 文件与依赖

实现保持在最小必要文件集合：加载入口、资源采集与接口模块、资源条 JavaScript、CSS、依赖声明及相应测试。正式设计、实施计划和使用文档放在 `docs/`。

Python 依赖使用 `psutil` 和 `nvidia-ml-py`；ComfyUI 现有 `aiohttp` 用于本地接口。不会另外安装同名 `pynvml` 分发包。本机上述依赖已经核实可用，当前 NVIDIA GPU 的利用率、温度与显存接口已完成读取检查；这些检查仅证明采集来源可用，不等于扩展已经实现。

项目创建前为空目录；现已建立 Git 仓库。设计文档和后续实现使用本地 `feat/resource-monitor` 分支；用户已于实施阶段追加授权：完成后提交、合并并正常推送到指定 GitHub 仓库，保留远程既有许可证和历史；未授权创建 Pull Request。

## 验收标准

1. 当前 ComfyUI 能加载扩展，菜单栏出现五项指标，工作流不需要新增节点。
2. CPU 利用率的采样基线正确；内存和显存的百分比、容量及单位一致；GPU 数据对应所选设备。
3. 默认每秒更新；各项开关、GPU 选择、刷新间隔和关闭监控即时生效，刷新不产生重叠请求。
4. 缺少依赖、无 GPU、单项 NVML 失败以及 API 断线时，界面正确显示可用项与不可用项；恢复后重新显示实时数据。
5. 菜单正常模式、浮动模式、Focus Mode 切换、页面隐藏与恢复、宽窄窗口下，挂载和刷新行为符合设计。
6. 通过与范围匹配的 Python 和 JavaScript 检查，以及本机 ComfyUI HTTP 接口和浏览器验收。性能结论依据测量结果，不预先承诺固定 CPU 开销比例。
7. 新增前后端数据契约与并发采样行为按仓库高风险规则执行：先建立 Implementation Plan，实施完成后进行独立只读审查；最终验收必须对应交付代码状态。

本规格确认后再建立实施计划。实际写入、运行验证及安装接入均遵守项目授权与路径规范，保留已有 ComfyUI 工作区改动。
