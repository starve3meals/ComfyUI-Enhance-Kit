# 分类提示词库设计规格

日期：2026-10-08

状态：用户已确认功能方案及官方节点样式要求；本文待审阅，尚未进入实施。

代码基线：`6e466da`；设计分支：`docs/prompt-library-design`。

## 目标与已确认范围

在 EnhanceKit 中新增一个「提示词库」节点，让用户按任务或模型维护常用提示词，在不同工作流中重复使用。

用户已确认：

- 提示词库跨工作流共享，保存在 ComfyUI 用户数据目录，重启后保留，更新插件不会覆盖。
- 用户维护一级分类；每条提示词包含标题和正文，并且属于一个分类。
- 节点先选择分类，再选择该分类下的标题，预览正文，输出一个 `STRING`。
- 提示词支持新增、编辑、重命名、删除和移动分类；分类支持新增、重命名和删除空分类。
- 点击运行时读取共享库中的最新正文，将其固定为本次提交的内容；排队或执行期间修改库，下次提交生效。
- 节点样式与 ComfyUI 官方节点统一，保持整洁、美观。

分类用于用户自行区分任务或模型适用范围，不执行模型兼容判断，也不限制工作流必须使用某个分类。不同节点独立保存自己的分类和提示词选择。

首版不包含多级分类、多分类标签、变量替换、随机抽选、云同步、导入导出或版本历史。正文按原文输出，不拼接前后缀，不展开通配符，不改变换行或空白。

## 节点与使用流程

拟注册节点标识 `EnhanceKitPromptLibrary`，显示名称「提示词库（EnhanceKit）」，分类为 `EnhanceKit/Prompt`，输出名为 `prompt`，类型为 `STRING`。

| 控件 | 行为 |
| --- | --- |
| 分类 | 原生下拉框，显示用户创建的分类名称，内部以稳定 ID 引用 |
| 提示词 | 原生下拉框，仅列出所选分类下的标题，内部以稳定 ID 引用 |
| 正文预览 | 原生多行文本控件，只读，可选中和复制内容，可滚动查看长文本 |
| 管理提示词库 | 原生按钮，打开管理面板并定位当前分类及提示词 |
| `prompt` 输出 | 返回本次提交已解析的完整正文 |

首次添加节点时没有隐式选择，也不预置示例分类或提示词。空库显示「请先创建分类和提示词」，通过管理按钮完成添加后选择使用。

切换分类时清除此前的提示词选择及预览，要求选择新分类下的标题，避免输出上一个分类的正文。相同分类的多个节点可选择不同提示词；选择行为只改变当前节点。

新增或重新选择提示词时读取正文。打开工作流、浏览器重新获得焦点和保存管理操作后刷新库与预览；不做持续轮询。预览属于最近一次读取的内容，运行前再次解析，不能依靠预览缓存保证最新性。

库中的分类或提示词已删除时保留失效引用并显示「已删除，请重新选择」，清除预览，禁止此次提交继续使用旧正文。不自动替换为第一条提示词。

提示词移到其他分类后，已选中它的节点跟随其稳定 ID 更新分类，并保留选择。切换分类仍按前述显式清除规则处理。

## 管理面板与视觉要求

管理面板采用一个集中编辑窗口：分类列表、当前分类的提示词列表、标题及正文编辑区。打开时定位当前节点选择，用户也可以在面板内切换分类维护其他内容。窄窗口可将列表与编辑区纵向排列，长列表和正文各自在区域内滚动。

编辑采用明确的「保存」操作。保存成功后刷新当前页面中的相关节点；失败时保留编辑内容，显示可操作的错误信息。关闭或切换编辑对象时，存在未保存修改则提示保存、放弃或取消。

分类名称在当前用户库中唯一；同一分类中的提示词标题唯一；不同分类可以使用相同标题。名称和标题去除首尾空白后校验非空，唯一性按完整字符串判断。正文不去除空白，允许空字符串，支持中文、Unicode 和多行文本。

删除提示词前说明引用它的节点需要重新选择并要求确认。有提示词的分类不能直接删除；先移动或删除其中的提示词，空分类才可删除。

视觉约束：

- 沿用官方节点标题栏、背景、边框、插槽、字体和控件间距，不绘制另一套节点外壳。
- 优先使用官方下拉框、文本控件、按钮和弹窗入口；确需扩展的管理布局使用 ComfyUI 主题变量，样式限定在本扩展面板内。
- 深浅主题都应有清晰的文字对比度、焦点状态和选中状态；不固定另一套品牌配色，不覆盖全局 CSS。
- 节点宽度和预览高度可随节点尺寸调整，长标题和长正文不得挤压输出插槽或按钮。
- 正文和标题作为文本显示，不将用户内容作为 HTML 插入。
- 不引入额外 UI 框架，不要求用户关闭 Nodes 2.0 或更改全局渲染设置。

## 共享范围与数据保存

共享范围是**同一 ComfyUI 用户配置下的所有工作流**。普通单用户模式使用 `default` 用户；启用多用户模式时，通过 ComfyUI 自己的用户解析接口分开保存，不跨用户共用提示词。

固定相对路径为 `enhance-kit/prompt-library.json`，由 `PromptServer.instance.user_manager.get_request_user_filepath` 定位。在默认目录配置下，该文件位于 `ComfyUI/user/default/enhance-kit/prompt-library.json`。遵循 ComfyUI 自定义用户目录，不写到插件目录或工作流文件旁边，不接受客户端提供存储路径或用户 ID。

文件结构：

```json
{
  "schema_version": 1,
  "revision": 1,
  "categories": [
    { "id": "category-uuid", "name": "Flux 写实" }
  ],
  "prompts": [
    {
      "id": "prompt-uuid",
      "category_id": "category-uuid",
      "title": "人物摄影",
      "text": "完整提示词正文"
    }
  ]
}
```

示例 ID 仅用于说明；实际 ID 由服务端生成。`revision` 为成功写入后的单调递增整数，用于防止多个页面互相覆盖修改。分类和提示词 ID 不因重命名、正文编辑或移动而变化，删除后不复用。

不存在数据文件时返回空库，在首次保存时创建。文件损坏、版本不受支持、读取权限或写入失败时明确报错，不能将损坏文件当作空库重新覆盖。

写入采用同一用户库的串行更新、版本检查和同目录原子替换，避免写出半截 JSON。锁及文件操作归提示词库模块所有；文件读写不阻塞 aiohttp 主事件循环。临时替换文件属于运行时数据，位于用户库文件同目录，成功后不保留。

## 组件、接口与职责

在现有扩展加载入口中注册节点和本扩展接口。提示词库存储及管理接口、前端选择及编辑界面、节点文本输出分别承担自己的职责；资源监控采集器不参与提示词处理。不修改 ComfyUI 核心源码，不新增 Python 或前端依赖，不访问互联网。

拟使用以下同源接口，均按请求的 ComfyUI 用户配置解析：

| 接口 | 职责 |
| --- | --- |
| `GET /enhance-kit/prompt-library` | 获取当前用户库、分类、提示词和 revision；响应不可缓存 |
| `POST /enhance-kit/prompt-library` | 提交单次管理操作，要求 `expected_revision`，成功返回更新后的库 |
| `POST /enhance-kit/prompt-library/resolve` | 按提示词 ID 获取当前所属分类、标题、正文快照及 revision；不修改库 |

管理操作为 `category.create`、`category.rename`、`category.delete`、`prompt.create`、`prompt.update`、`prompt.delete`。`prompt.update` 可同时更新标题、正文和所属分类。请求仅包含该操作需要的字段，服务端校验 ID 存在、分类归属和名称唯一性，不接受整库覆盖上传。

版本冲突返回 HTTP 409，前端保留未保存内容，要求刷新后重新处理；引用不存在返回 404，非法操作或字段返回 400。存储故障按实际失败返回错误，不能用成功状态吞掉故障。具体错误文字保持简短，不在日志中打印正文。

## 最新内容与执行快照

正常浏览器提交流程为：读取节点当前选择 → 等待解析接口返回最新正文 → 将正文固化到本次执行输入 → 提交 ComfyUI 队列 → 节点原样返回正文。

执行节点只消费本次输入的文本快照，不在执行期间重新读取共享库。正文属于执行输入，内容变化应自然改变 ComfyUI 缓存依据；不采用强制每次执行或关闭缓存来规避旧内容问题。

运行前解析失败、引用失效或用户在等待期间改变选择时，不能继续使用旧的预览内容。处理晚返回请求时核对节点与选择仍有效，避免快速切换下拉框、工作流或用户配置导致串用内容。

提交接入必须使用本机前端中**会等待完成**的序列化或提交扩展点。本机前端的 `widget.beforeQueued` 调用没有等待 Promise，不能在该回调中发起异步读取后假定完成。实施计划需要核实实际的序列化入口及 Nodes 2.0 行为，并以断网、延迟及库更新后的提交测试证明取值顺序；不能依赖后台轮询或修改 ComfyUI 核心实现。

每个提示词的解析响应内部一致。本次队列固定各节点已取得的正文，不承诺并发编辑时整个工作流的所有提示词来自同一个全库 revision。

工作流保存稳定的分类和提示词引用，预览正文只作为界面状态。重新运行时必须成功解析本地库；将工作流带到另一台机器不会自动带走共享库，也不能以旧预览冒充有效引用。

不经过浏览器的 API 客户端需要先调用解析接口，再提交正文快照。导出的执行 API 工作流代表当次已解析文本；直接重放该 API 请求不会自动刷新库。这一边界在使用说明中明确，避免误解「最新」的获取时机。

## 验收标准

1. 节点能被 ComfyUI 加载，输出一个可连接官方文本编码节点的 `STRING`，中文、多行、空白和空正文按原文保留。
2. 分类、提示词管理及跨分类移动符合唯一性和归属规则；重启后保留；插件更新不覆盖用户文件。
3. 多个工作流独立保持选择，共享库的正文更新在下一次提交时生效；已经排队的任务内容保持不变。
4. 重命名不破坏引用，移动后引用跟随；删除、空库、断网或解析失败均不得静默输出其他条目或旧正文。
5. 并发修改的 revision 冲突、写入失败和损坏文件不会丢失已有数据；多用户配置不得相互读取或修改库。
6. 快速切换分类、节点、工作流以及请求乱序时，预览和提交正文对应正确选择；相关前端监听和请求在关闭时清理。
7. 与官方节点并排检查 Nodes 2.0、传统渲染、深浅主题、节点缩放、长文本和窄窗口，外观协调且控件可用，不影响其他节点或资源条。
8. 通过匹配范围的 Python 存储及接口检查、JavaScript 状态与提交检查、本机 HTTP 和浏览器验收，以及对应最终代码状态的独立审查。
